# Know Your GPA：项目介绍

## 一句话介绍

Know Your GPA 是一个本地运行的 GPA 雷达图识别工具。把微北洋 GPA 页面截图拖进网页，它会尝试还原课程数量、每门课的成绩和学分，并计算加权成绩、平均 GPA 与总学分。

这个项目不是学校官方工具，也不会修改或上传任何教务数据。它更像一个“看懂雷达图的计算器”：先自动识别，再允许使用者手动核对和修正。

## 我为什么做这个项目

微北洋的 GPA 页面用雷达图展示成绩，视觉效果直观，但当我想知道具体的加权成绩、GPA 和各门课程数据时，单靠图片并不方便。逐门手算不仅费时间，也容易因为课程多、学分不同而出错。

于是我产生了一个很直接的想法：能不能把截图交给一个工具，让它自动读出雷达图，并把结果变成可以检查、修改和导出的表格？

Know Your GPA 就是围绕这个问题逐步完成的。

## 它能做什么

- 选择、拖入或直接粘贴 GPA 截图；
- 自动定位雷达图的圆心、课程轴和成绩折线；
- 推测每门课程的成绩与学分；
- 计算加权成绩、平均 GPA 和总学分；
- 在截图上显示识别点，方便检查结果；
- 手动拖动成绩点、学分点、圆心和外圆；
- 直接修改课程名称、成绩、学分和课程数量；
- 一键复制汇总，或导出 CSV 表格；
- 对裁剪、文字遮挡等特殊截图给出低置信度提示和重点核对标记。

所有图片都只在本机浏览器中处理，不会上传到服务器。

## 最简单的使用方法

1. 在 Windows 中双击 `雷达图GPA.bat`。
2. 点击“选择图片”，或者把截图拖进页面，也可以按 `Ctrl + V` 粘贴截图。
3. 等待自动识别，查看右侧的课程表和汇总结果。
4. 如果标记没有贴合原图，可以在左侧切换模式并拖动红色成绩点、黄色学分点或圆心。
5. 核对完成后，复制汇总或导出 CSV。

普通使用不需要安装 Python、Node.js，也不需要联网。默认浏览器能够打开本地 HTML 文件即可。

## 它大致是怎样工作的

这个工具没有读取学校数据库，而是在分析截图中的颜色和几何关系。

它会先寻找雷达图所在的蓝色区域和圆心，再统计从圆心向外发散的课程轴。白色成绩折线距离圆心越远，通常代表成绩越高；学分扇形的半径则用来估算学分。识别完成后，程序按照课程学分重新计算加权成绩和 GPA。

对于存在文字涂鸦或圆形裁剪的截图，程序不会继续把整片白色区域当成成绩折线，而是寻找“两侧为蓝色的细白线”，再根据相邻线段的连续关系重建被遮住的部分。若图片已经裁掉了学分外圈，则会结合截图中仍然可见的总学分和已知参考关系进行约束，同时降低置信度并提示人工核对。

它本质上是视觉估算，不是从原始成绩数据中直接读取，因此“自动识别 + 人工确认”始终比完全相信自动结果更可靠。

## 这个项目是怎样完成的

我是一个对代码并不熟悉的人，这个项目由我全程通过 Vibe Coding 完成。

这里的 Vibe Coding，不是输入一句话后等待 AI 自动交付成品，而是一个反复协作的过程：

- 我提出真实问题，决定工具应该解决什么；
- 我提供截图、正确学分和错误案例；
- 我实际使用页面，指出“哪里还是不对”；
- AI 帮助阅读代码、实现算法、修改界面和编写测试；
- 我根据真实结果继续判断、纠正和提出下一轮要求。

例如，一张被文字涂鸦遮挡的截图曾经被错误识别为多门满分课程。通过多轮对比，我补充了截图顶部学分卡中的总学分等关键信息，项目才逐步识别出圆形区域其实是被裁剪的成绩内圈，并改用可见白线重建折线。

因此，我在项目中的角色更接近产品提出者、测试者和决策者：我不一定亲手写出每一行代码，但我定义问题、提供事实、判断结果，并推动项目从一个想法变成可以运行的工具。代码实现由 AI 协助完成，最终效果则来自持续的人机协作。

## 项目中的主要文件

| 文件或目录 | 用途 | 非技术理解 |
| --- | --- | --- |
| `radar_gpa.html` | 主网页和识别算法 | 真正使用的工具主体 |
| `雷达图GPA.bat` | Windows 启动入口 | 双击它即可打开网页 |
| `README.md` | 简要使用和开发说明 | 快速说明书 |
| `docs/PROJECT_OVERVIEW.md` | 项目背景与完整介绍 | 你正在阅读的文档 |
| `tests/fixtures/` | 不同类型的 GPA 截图 | 用来检查识别是否正确 |
| `tests/browser/` | 真实浏览器回归 | 防止测试解码与页面表现不一致 |
| `tests/js/test_detector.js` | 图片识别回归测试 | 防止改完一张图却弄坏其他图片 |
| `tests/python/` | Python 自动测试 | 检查计算和基础功能 |
| `radar_gpa.py`、`radar_gpa_gui.py` | 早期手动标点版本 | 项目探索过程的保留版本 |
| `radar_auto_detect.py` | 旧版 OpenCV 自动识别实验 | 早期视觉算法方案 |
| `references/` | 雷达图绘制参考代码 | 帮助理解原图如何把成绩画出来 |
| `experiments/` | 早期算法实验 | 保留探索过程，但不参与正式测试 |

`experiments/` 中以 `test_` 开头的 Python 文件，大多是开发早期为了验证圆心、边界、课程轴和学分识别而留下的实验。

## 如何保证修改没有把项目弄坏

项目保留了多张不同学期、不同尺寸和不同遮挡程度的测试截图。每次修改识别算法后，都会重新检查这些图片，而不是只看当前正在修复的一张。

项目同时包含 JavaScript 图片回归测试和 Python 自动测试，用于核对课程数量、成绩、学分、GPA 计算、文件处理和异常情况。真实浏览器测试还会验证 JPEG 在浏览器中的实际解码结果，尽量减少“测试通过但页面里不一样”的情况。

自动测试能够降低回归风险，但不能证明所有新截图都能百分之百识别。因此页面仍然保留了置信度、识别标记和手动校正功能。

## 当前局限

- 它针对微北洋 GPA 雷达图设计，不是通用成绩单 OCR；
- 不同主题、压缩方式、截图比例可能影响颜色判断；
- 课程名称通常需要使用者自己填写或修改；
- 大面积文字、贴纸或裁剪会让部分原始信息永久丢失；
- 强遮挡场景可能使用项目内的参考关系进行恢复，不代表所有类似截图都能自动还原；
- 自动结果仅供整理和参考，正式成绩应以学校系统为准。

## 可以继续发展的方向

- 支持更多页面主题和截图样式；
- 为每门课程单独显示识别可信度；
- 用更通用的 OCR 读取总学分和页面文字；
- 允许使用者主动上传一张参考学期截图，而不是依赖项目内置关系；
- 把早期实验代码整理成更清晰的模块；
- 打包成更像普通软件的 Windows 应用；
- 增加识别前后的对比报告，方便快速发现错误。

## 最后想说

这个项目对我而言，不只是一个 GPA 计算工具，也是一次学习如何把想法变成产品的实践。

Vibe Coding 降低了编程的起点，但没有替代思考、判断和耐心。真正让项目不断变好的，是明确问题、提供正确事实、反复测试，以及在结果不对时继续追问“为什么”。即使不熟悉代码，也可以参与软件创造；重要的是知道自己想解决什么，并愿意持续验证它是否真的解决了问题。
